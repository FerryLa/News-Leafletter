# [마일스톤4-Day5] 에버노트 데이터 학습 통합

## 📌 간단 개요
기존 에버노트 뉴스 데이터를 학습 파이프라인에 통합하고 ML 학습 방향 설계. 에버노트 HTML/ENEX 파싱, DB 통합, 3가지 학습 옵션 평가.

## 🎯 목표
1. **에버노트 데이터 파싱**: HTML/ENEX 형식 파싱 및 메타데이터 추출
2. **DB 통합**: articles 및 article_labels 테이블에 통합 저장
3. **학습 방향 결정**: 3가지 학습 활용 방안 평가 및 선택
4. **통합 가이드 작성**: 에버노트 데이터 import 및 활용 문서화

## 🔧 개선사항

### 1. 에버노트 데이터 구조 분석
**기존 문제**:
- 에버노트 데이터 활용 방안 불명확
- 데이터 포맷 파악 필요
- 기존 데이터와 통합 방법 모름

**개선 방향**:
- [ ] **데이터 포맷 확인**
  - HTML 내보내기 파일 구조 분석
  - ENEX (Evernote XML) 파일 스키마 파악
  - CSV 변환 가능성 확인

- [ ] **필드 매핑 계획**
  ```
  에버노트 제목       → articles.title
  에버노트 내용       → articles.content
  에버노트 태그       → article_labels.label_value
  에버노트 생성일     → articles.published_at
  에버노트 노트북명   → articles.category
  에버노트 URL       → articles.url (본문 내 링크 추출)
  ```

- [ ] **데이터 품질 확인**
  - 기사 수
  - 태그 분포
  - 날짜 범위
  - 본문 길이 통계

### 2. 데이터 파싱 모듈
**기존 문제**:
- 에버노트 파일 직접 파싱 어려움
- HTML 태그 정리 필요
- 메타데이터 추출 복잡

**개선 방향**:
- [ ] **HTML 파싱**
  - BeautifulSoup4로 HTML 구조 파싱
  - 제목, 본문, 생성일 추출
  - 태그/노트북 메타데이터 추출

- [ ] **ENEX 파싱** (선택)
  - XML ElementTree로 ENEX 파싱
  - note, title, content, created, tag 추출
  - HTML content 텍스트 변환

- [ ] **HTML → 텍스트 변환**
  - 불필요한 태그 제거 (<style>, <script>)
  - 포맷팅 유지 (줄바꿈, 리스트)
  - 이미지/링크 처리

- [ ] **URL 추출**
  - 본문 내 뉴스 URL 추출
  - 여러 URL 중 대표 URL 선정
  - URL 없으면 제목으로 검색

### 3. DB 통합
**기존 문제**:
- 에버노트 데이터 별도 저장 필요
- 기존 데이터와 중복 가능
- 레이블 변환 로직 필요

**개선 방향**:
- [ ] **articles 테이블에 삽입**
  - `source_name = 'evernote'` 표시
  - `fetched_at = 에버노트 생성일`
  - article_id 자동 생성 (UUID)

- [ ] **중복 체크**
  - 제목 + 날짜 기준 유사도 체크 (Levenshtein distance)
  - 유사도 > 0.9면 중복으로 간주
  - 이미 존재하는 기사는 건너뛰기 또는 병합

- [ ] **태그 → 레이블 변환**
  - 에버노트 태그를 `article_labels` 테이블에 저장
  - `labeled_by = 'manual'` (사용자가 직접 태그 지정)
  - `confidence = 1.0` (수동 레이블 신뢰도 최고)

- [ ] **데이터 보강**
  - 키워드 자동 추출 (Day 1 모듈 활용)
  - 섹터 자동 분류 (기존 SectorClassifier)
  - content_length 계산

### 4. 학습 데이터 증강
**기존 문제**:
- 에버노트 데이터만으로 부족
- 자동 레이블링 필요
- 섹터 정보 없음

**개선 방향**:
- [ ] **자동 레이블링 적용** (Day 2 모듈)
  - 키워드 기반 레이블 자동 추가
  - 기존 에버노트 태그와 병합
  - 중복 레이블 제거

- [ ] **키워드 추출** (Day 1 모듈)
  - TF-IDF로 주요 키워드 추출
  - `keyword_extracted` 컬럼 채우기

- [ ] **섹터 분류** (기존 classifier)
  - `SectorClassifier`로 자동 분류
  - `primary_sector`, `secondary_sector` 설정

- [ ] **통합 검증**
  - 파싱된 기사 수 확인
  - 레이블 분포 확인
  - 섹터 분포 확인
  - 품질 체크 (Day 4 모듈 활용)

### 5. 학습 파이프라인 설계 🧠
**기존 문제**:
- 에버노트 데이터 활용 방향 불명확
- 학습 전략 미수립
- ML 실험 계획 없음

**개선 방향**:
- [ ] **3가지 옵션 평가**

  **옵션 A: 초기 학습 데이터 (유저 프로파일링)**
  - **개념**: 에버노트에 저장 = 사용자가 관심 있는 기사
  - **활용**: 유저 관심사 파악 → 추천 시스템 초기 모델
  - **장점**: 개인화 추천 시스템 부트스트랩 가능
  - **단점**: 단일 사용자 데이터, 일반화 어려움
  - **평가 기준**:
    - 에버노트 기사 수 (> 100개면 유효)
    - 태그 다양성 (> 10개 태그)
    - 시간 범위 (> 6개월)

  **옵션 B: Gold Standard 레이블 데이터**
  - **개념**: 에버노트 태그 = 사용자가 직접 지정한 레이블
  - **활용**: 자동 레이블링 모델 훈련용 ground truth
  - **장점**: 높은 품질의 레이블 데이터
  - **단점**: 데이터 수 부족 시 학습 어려움
  - **평가 기준**:
    - 레이블 있는 기사 비율 (> 70%)
    - 레이블 분포 균형 (각 레이블 > 10개)
    - 레이블 일관성

  **옵션 C: 임베딩 학습용 Corpus**
  - **개념**: 에버노트 기사 = 추가 텍스트 데이터
  - **활용**: 임베딩 모델 fine-tuning, 도메인 특화 벡터 학습
  - **장점**: 데이터 증강, 임베딩 품질 향상
  - **단점**: 대량 데이터 필요 (> 1,000개)
  - **평가 기준**:
    - 전체 기사 수 (> 500개)
    - 평균 본문 길이 (> 500자)
    - 도메인 특화 정도

- [ ] **선택 기준 정립**
  - 각 옵션별 필요 조건 확인
  - 에버노트 데이터 특성 평가
  - 마일스톤 5 목표와 정렬
  - 최종 방향 선택 및 문서화

- [ ] **구현 계획 수립**
  - 선택한 방향에 따른 다음 단계
  - 필요한 추가 데이터 수집 계획
  - 평가 지표 정의

## ✨ 기대효과

### 1. 데이터 증강
- **효과**: 에버노트 데이터 추가로 학습 데이터 20-50% 증가
- **지표**: 전체 기사 수 1,000 → 1,200+ 개

### 2. 고품질 레이블 확보
- **효과**: 사용자 수동 태그로 레이블 품질 향상
- **지표**: 수동 레이블 비율 10% → 30%

### 3. 개인화 부트스트랩
- **효과**: 유저 관심사 파악으로 추천 시스템 초기 모델 구축
- **지표**: 유저 프로파일 정확도 > 80%

### 4. ML 방향 명확화
- **효과**: 마일스톤 5 실험 방향 구체화
- **지표**: 3가지 옵션 평가 및 1가지 선택 완료
